# 给开发 Agent 的实施交接

## 任务目标

在 `hamletroyophelia/openfoam-cfd-agents` 现有项目中实施《系统设计》的增量扩展。不得把本方案包当成已经运行的系统，也不得在未授权时直接发布或修改生产算例。

开始时先读取仓库当前 `AGENTS.md`（若存在）、README、架构、`domain.py`、适配器和测试；本方案保留 2026-09-04 基线，并在 2026-09-05 重新读取 README 与 domain.py，不能覆盖之后真实发生的代码变化。记录工作树状态，保留无关修改。先执行既有测试，再决定增量设计。

## 不可破坏的约束

保留确定性验收、全部尝试记录、显式审批、有限修复与报告只读结论。上游返回 success、进程正常结束或人工批准都不能让科学检查自动 passed。

不统一混用 Foundation/OpenCFD 的模板、源码和工具名称。不复制授权未确认的代码。不引入用户密钥、固定主机名、专属 CPU 数量或绝对目录作为公共默认值。

不得把本文件建议的新工具名称当作当前存在的命令。实现前先定义并测试契约。不要为了让演示变绿而放宽容限、删掉失败样本或伪造实测数据。

## V2 的提交顺序（优先于新增 UI）

每项是独立的可审查变更，不要求一次重写整个项目：

1. **有限数判定与 schema 迁移**：处理 SOURCE_REVIEW 中发现的问题，加入 V2-01/02；保持正常有限数比较和已有 CLI 行为。
2. **能力矩阵与物理语义**：区分声明/契约/运行/科学测试，记录单位、几何映射和版本；执行 V2-13/14。
3. **持久作业与故障恢复**：完成幂等、启动窗口、取消、检查点与租约核对；执行 V2-03 至 V2-09、V2-12。
4. **证据依赖与修改审批**：做受影响结论失效、复用与审批绑定；执行 V2-10/11。
5. **科学研究与数据交付**：沿用原 P2/P3 实现，覆盖 V2-15 至 V2-20，不让性能测试冒充精度研究。
6. **安全与平台发布**：V2-21 至 V2-24 通过后再扩展调度器、第三方 MCP 和可选 VibeFlow。

不要安装 `config/reliability-policy.example.yaml` 就声称上述能力已生效；当前它仅是待实现的配置契约。先建立后端校验，再开放可写工具。

## P0 — 保护现有核心

实施：建立当前能力矩阵；复核 StageResult/WorkflowManifest 和两个 MCP adapter；设计版本化 schema 迁移；记录已有测试和欠缺。

验收：既有 CLI 与序列化结果保持可读；只有规则计算状态；修复创建新尝试；当前已实现/未实现功能在文档中一致。

提交边界：一个只包含基线测试、必要缺陷修复和迁移设计的独立变更，不混入 UI 或新框架。

## P1 — 可靠的计算闭环

实施：定义 JobSpec/JobRecord；实现持久化队列与单 worker；增加受限网关、真正的 MCP 客户端连接管理、运行状态/日志/取消；让本地 OpenFOAM 适配器成为首个受测 worker 后端。

验收：

- 同一幂等键不会启动两次；同一 case revision 不会有两个写入者。
- 网关/客户端断开后作业继续受管；worker 重启能核对活跃进程，不能重复发起。
- OpenFOAM 不存在、分支错误、模块缺失和非法路径均返回可诊断状态。
- 超出 CPU/内存/并发预算时拒绝启动；取消只影响指定进程组。
- 至少一个小型真实算例留下输入哈希、运行环境、命令、原始日志、输出和结果。

无法在当前开发环境跑真实 OpenFOAM 时，明确写“真实集成未测”，保留单元测试与 fixture 结果，不能宣称 P1 端到端通过。

## P2 — 数值验证、统计与性能选择

实施：多目标量网格/时间步/域 study；适用性检查与 inconclusive 状态；HPC benchmark；带不确定度的统计；合格候选配置选择和最后联合复核。

验收：

- 三网格正常收敛、非单调、退化差值、采样噪声主导和不适用加密均有测试。
- 拟推荐的粗/中网格有对应误差证据，而不是引用细网格误差冒充。
- 不规则时间采样的加权均值正确；重复重启时刻有去重规则；相关块不能虚增有效样本。
- 固定步数基准不会输出网格精度结论；串行回退、受干扰或失败样本不进入原并行配置排名。
- wall time、每步耗时、core-hours 与内存定义清楚，强扩展允许非单核基准。
- 无合格配置、预算耗尽或统计证据不足会得到失败/不可判定报告，而不是强行推荐。

先用可解析的人造函数/统计序列测试算法，再做真实算例对比；两类证据必须分开标记。

## P3 — 可复现后处理与报告

实施：ParaView batch worker、版本化 recipe、CSV 规范、图像与状态文件、报告索引和独立审查。

验收：

- 相同输入与 recipe 可重放；每张图有来源 CSV/场文件和脚本参数。
- 压力/运动学压力、参考面积/密度、cell/point 变量和时刻正确。
- 相机、色标、截面和涡阈值明确；动画在目标 Linux 环境有受测输出路径。
- 报告可以包含失败或探索性结果，但不能改写状态或隐藏不确定性。
- 无 GUI 的受支持环境可完成默认后处理；可选 MCP 渲染后端不可阻断基本报告。

## P4 — 集群与可选 VibeFlow 控制台

实施：先做一个受测调度器适配器，再扩展其他平台；控制台通过认证 API/MCP 接入。VibeFlow 项目与 Python 核心隔离，不绑定为运行必需品。

验收：

- 断线、超时、排队、取消、节点失效、调度器重排队状态有正确映射。
- UI 与 CLI 所见状态一致；重复点击提交不产生重复作业。
- 凭据不出现在前端包、日志和 Git 历史；不同项目的资源访问受隔离。
- 不连接 VibeFlow 也能运行全部核心科学流程。
